# v1.0 테스트 후보 (rc.1)

> 대상: 이 디자인 시스템으로 실제 화면을 만들어 볼 개발팀.
> 상태: **테스트 후보** — 로컬 체크포인트 `checkpoint/v1.0-candidate`. npm · Storybook 배포와 정식 `1.0.0` 출시는 하지 않았습니다.
> 버전: `package.json`은 `0.1.0` 그대로입니다. "rc.1"은 이 후보를 부르는 이름이며, 실제 버전 번호는 10절 R-1에서 정합니다.
> 순서: ① Figma 점검 · 보완 → ② Storybook 동기화 → ③ 전체 QA → ④ 이 문서. 진행 기록은 [progress.md](./progress.md) 맨 위 절.

**판단 — 지금 디자인 시스템만으로 실제 웹 서비스 화면을 만들 수 있는가?**
관리 · 운영형 웹 서비스의 **입력 화면, 목록(표) 화면, 대시보드 화면**은 지금 컴포넌트와 규칙만으로 만들 수 있습니다. Figma와 Storybook에
같은 구성의 사용 예시를 두고 실제로 조립해 확인했습니다(필수 표시 · 오류 · 저장 중, 검색 · 필터 · 결과 없음 · 페이지 이동, 조회 조건 · 지표 · 차트 · 데이터 상태).
다만 다음은 아직 디자인 결정이 필요합니다(11절 V-1 – V-5): 입력 칸 기본 상태의 도움말, 버튼 안 처리 중 표시, 주의(Warning) 알림, Dialog 크기,
체크박스 · 라디오 묶음 오류. 그리고 Figma에 없어 만들지 않은 UI가 있습니다(9절).

- CSS 변수 이름 = Figma Dev Mode에 보이는 이름(모든 변수에 WEB code syntax `var(--…)`). 이름 바꾸기 · 삭제는 호환 깨짐으로 다룹니다([breaking-changes.md](./breaking-changes.md)).
- 색 변수는 쓰는 곳에 맞게 범위(scopes)를 좁혔습니다(Figma에서 Component 토큰이 먼저 보이고 Primitive · Theme 색은 숨김).
- Figma와 코드 스냅숏은 8개 묶음 체크섬이 모두 같습니다(8절). 이름 없는 Component 변수 7개(`default` · `hover` …)는 묶음 경로가 없어 CSS로 내보내지 않습니다.
- 이 후보에서 추가: 필수 표시 4개, 파일 실패 글자 1개, 효과 2개(기존 그림자와 같은 값).
- 남은 정리: 쓰이지 않는 변수 · 이름이 역할과 다른 입력 칸 `label/*` 토큰(V-8 · V-10), 문서 프레임의 원격 변수(V-11).

## 4. 주요 변형 · 상태

- Figma 변형은 모두 Storybook "전체 보기"의 매트릭스로 렌더링하고, 변형마다 크기 · 위치 · 픽셀 · 글자 위치 · **글자 색**을 Figma와 비교합니다.
- 공통 상태: 기본 · Hover · Pressed · Focus(키보드 포커스 테두리) · Disabled · Read-only · Error · Selected · Expanded · Loading.
- **이 후보에서 추가**

| 컴포넌트 | 추가 | 코드 |
| --- | --- | --- |
| Input · Textarea · Select · DatePicker | 필수 입력(라벨 뒤 점) | `required` |
| FileUploaderItem | 업로드 실패 | `status="error"` |
| Table | 칸 내용 가운데 정렬(Figma 표와 같음) | 기본 동작 |
| Breadcrumb | 펼친 메뉴 항목 Hover · Pressed 글자 색 | 버그 수정 |

## 5. Storybook 사용 방법

```bash
npm install
npm run storybook   # http://localhost:6006
```

- 사이드바: **기초**(디자인 토큰 · 포커스) → **컴포넌트**(`사용 방법` 문서 · `전체 보기` 검증 매트릭스 · `직접 체험` 등) → **사용 예시**(화면 단위 조합).
- 컴포넌트를 처음 쓸 때는 `사용 방법` → `직접 체험`(Controls로 Props 변경) 순서로 봅니다. 화면을 만들 때는 `사용 예시`의 구성을 따릅니다.
- Storybook MCP(`http://localhost:6006/mcp`)로 AI 도구가 같은 문서를 읽을 수 있습니다([developer-guide.md](./developer-guide.md)).

- 가져오기: `import { … } from 'platform-design-system'`, 스타일 `platform-design-system/styles.css`, 글꼴 `platform-design-system/fonts.css`.
- 공개 50 · 보조 32 · 타입 129 · 상수 45 · 함수 3 · 아이콘 35. 내부 부품 7 · 내부 API 13은 쓰지 않습니다(하위 호환 보장 없음) — [public-api.md](./public-api.md).
- 이 후보의 API 변경은 **추가만** 있습니다: `required`(입력 칸 4종), `FileUploaderItem status="error"`, `FILE_UPLOADER_ITEM_STATUSES`의 `'error'`,
  `TableProps`의 `id`(실행 시에는 이미 전달됐지만 타입이 막고 있었음).
  화면 변경: 표 칸 가운데 정렬. 자세한 내용은 [CHANGELOG.md](../CHANGELOG.md).

## 9. 남은 문제 · 제약

**자동으로 확인하지 못한 것(미검증)**

| 항목 | 지금 확인한 범위 | 남은 확인 |
| --- | --- | --- |
| 실제 화면 낭독기 | axe 규칙 · 접근 가능한 이름 · 설명 · 상태를 테스트로 확인 | NVDA · JAWS · VoiceOver로 실제 읽기 순서 · 문장 |
| 실제 Safari · 모바일 | Playwright WebKit(Windows)에서 정합성 · 상호작용 | macOS · iOS Safari 실기기, 터치 조작, 작은 화면 |
| 키보드 — 링크 Tab 이동(WebKit) | Chromium · Firefox는 Tab으로 링크 이동 | WebKit은 브라우저 기본 설정상 링크를 Tab으로 건너뜀(Safari 설정 · Option+Tab) — 제품 결함 아님 |
| 큰 데이터 | 스토리 수준(행 수십 개)의 표 · 차트 | 수천 행 표의 성능(가상 스크롤 없음), 많은 계열의 차트 |
| 확대 · 고대비 | 일부 스토리 수동 확인 | 200 % 확대 · Windows 고대비 모드 전체 점검 |
| 다크 모드 | — | Figma에 다크 테마가 없어 만들지 않음 |
| axe "검토 필요" | 위반 0. 판정하지 못한 항목 59개 스토리 1,182곳 — 색 대비 1,169(겹친 배경 · 반투명 · 비활성), 표 머리글 6, 허용되지 않는 aria 속성 후보 6, 이름 불일치 1 | 사람이 확인 |
| 콘솔 경고(제품 밖) | 외부 앱에서 라이브러리 경고 0 | Firefox: 의존성 `pretendard` 글꼴 파일의 이름 표 순서 경고 11건(글꼴은 정상 로드 · 화면 비교 통과, 숨기지 않음). Storybook: 동작 기록이 클릭 이벤트를 저장할 때 Storybook 10.6.2이 내는 자체 사용 중단 경고 3건 |

**만들지 않은 것(Figma에 없음)**: Popover · Combobox(자동 완성) · Drawer(Figma에서 삭제됨), 시간 선택, 상단 헤더 · 페이지 레이아웃 틀.
화면 틀은 사용 예시처럼 각 서비스에서 구성합니다.

**알려진 렌더링 차이**: 엔진별 글자 래스터화 차이(작은 글자의 밝기, 0.5–1px 글자 위치)는 검증 설정에 이유와 함께 기록돼 있습니다([browser-support.md](./browser-support.md)).

## 11. 남은 결정 사항

Figma 점검에서 찾았지만 디자인 의도를 정할 근거가 부족해 고치지 않은 항목입니다. **사용성 영향**이 있는 것과 정리 성격인 것을 나눴습니다.

### 사용성에 영향 있음

| # | 내용 | 지금 | 제안 |
| --- | --- | --- | --- |
| V-1 | 입력 칸(Input · Textarea · Select · Date Picker)의 기본 · 비활성 상태에 **안내 메시지**가 없음 — 메시지는 Focus · Completed · Error 변형에만. 토큰(`helper/default` · `helper/disabled`)은 있으나 쓰이지 않음 | 코드는 모든 상태에서 메시지(안내 `info`)를 보여 줌. Figma 속성 `Alert` 기본값이 켜짐이라 변형에 추가하면 기존 인스턴스 화면이 바뀜 | 회색 도움말 유형(input_message에 `Helper`)을 만들고 기본 · 비활성 변형에 추가(기본 끔인 새 속성으로) |
| V-2 | **버튼 처리 중 상태** 없음 | 규칙: 처리 중에는 Disabled + 옆에 Loading(sm)(Form 사용 예시) | 버튼 안 스피너 상태 — 변형 6종(종류 × 모양)마다 스피너 색 결정 필요 |
| V-3 | Alert · Toast에 **주의(Warning)** 상태 없음 — Badge에는 있음 | 안내 · 성공 · 오류 3종 | 주의 토큰(`brand-status/warning`)으로 Alert · Toast 변형 추가 |
| V-4 | Dialog **크기**가 하나(400px) | 내용이 많은 입력 화면은 좁음 | sm · md · lg 크기 정의 |
| V-5 | Checkbox · Radio **오류 표시** 없음(필수 동의 · 필수 선택) | 그룹 아래 오류 메시지를 따로 둬야 함 | 그룹 오류 메시지 규칙 · 예시 |
| V-6 | F85 점선 복원(범례 Dash Line · 간단 선 비교 선) | 복원한 점선 사용 | 실선이 의도였다면 Figma · 코드 · Rules 03 함께 변경 |
| V-7 | F82 표 편집 칸 Filter · Hover · Empty 칩만 State=Hover | 그대로 | 다른 유형처럼 컨트롤 Default로 통일할지 |
| V-13 | 표 칸 정렬 규칙이 없음 — Figma 표 칸은 모두 가운데 정렬(예시도 160px 칸 가운데) | 코드도 가운데로 맞춤(2026-10-20) | 긴 글(왼쪽) · 숫자(오른쪽) 열 정렬 규칙을 Rules 07에 정할지, 정하면 `TableColumn` · `TableCell` 정렬 옵션 추가 |
